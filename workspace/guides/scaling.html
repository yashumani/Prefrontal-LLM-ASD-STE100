Storage and scale / Measured limits

Keep context small. Keep source data native.

Context records describe meaning and bindings. Source facts stay in the system that owns them. One million source rows do not require one million governed semantic IDs.

The browser is a bounded authoring workspace. It is not a warehouse, a shared registry, a secure vault or a backup. It stores records on this device and origin. Export regularly. A source binding remains a descriptor until a real adapter and its access controls are qualified.

Origin includes the scheme, host and port. Repository paths on the same github.io origin are not separate security domains. A phone, another browser profile or a localhost preview uses different storage. Clearing site data, private browsing expiry or device loss can remove your only local copy.

Use explicit admission bounds

Bounds prevent the local workspace from silently accepting more than it can handle. They are limits on admitted inputs, not speed guarantees or a promise that every phone has the same storage quota.

BoundBrowser profile
Record versions in a workspaceUp to 1,000 total, including history.
Captured original filesUp to 1,000, within the same total workspace byte limit.
Saved workspace bytesUp to 2 MiB of UTF-8 serialized backup, including its wrapper, record history and originals.
One canonical recordUp to 64 KiB.
Direct dependenciesUp to 32 per record.
Resolved closureUp to 128 records, 1 MiB and depth 16.
Search pageUp to 100 results per page.
Trace eventsUp to 4,096. Further changes fail rather than silently dropping earlier events; the total byte limit still applies.
Integers and aliasesExact values within JavaScript's safe-integer range; ASCII aliases. Larger integers and non-ASCII aliases fail browser admission. Unicode display names and narrative are supported.

A long narrative, retained submissions and version history use the same workspace budget. A browser quota can fail before an application limit. Keep the unsaved input open, export it and reduce or migrate the workload. Do not lift a limit without measuring the affected validation, search, persistence and recovery paths.

Move to the governed core before the browser is full

  1. Export the workspace. Retain the original backup outside the browser. Do not publish it to GitHub.
  2. Validate and stage it. Use the Python browser-workspace bridge to check the exact schema, hashes, records, dependencies and source paths. Stage into a new local directory. No review or release state becomes trusted through this step.
  3. Review the sources and meaning. Verify source ownership, actual bytes, grain, freshness and typed relationships. Obtain independent human review of each exact version/hash and publish a complete permitted dependency set through the governed lifecycle.
  4. Admit the native binding. Qualify the source adapter's API, identity mapping, permissions, supported cuts, errors and revocation. Keep large raw text or fact tables in the native store; bind the reviewed context to them.
  5. Test the consumer. Search, resolve, revalidate and then execute through the consumer's native permissions. Retain latency, limits, failures and provenance for that actual workload.
  6. Plan operations. A multi-user service needs owned authentication, authorization, concurrency, backup, restore and monitoring. SQLite and a static page do not supply all of these by themselves.

Use the developer guide for the concrete bridge and contract. Extending a storage adapter does not automatically make different knowledge models equivalent. Keep IDs, versions, source provenance, approvals and invalidation rules through a migration. One provenance path has one hash across the workspace; changed source bytes need a new versioned or digest path. Do not overwrite historical provenance to make a migration pass.

Separate site limits from context limits

GitHub Pages serves static files. Its published limits include a 1 GB site limit, a soft 100 GB monthly bandwidth limit and a 10-minute deployment timeout. These limits do not increase browser storage or create a backend.

This site is an open-source project workspace. Pages is not intended as hosting for a commercial SaaS service or sensitive transactions. Do not add credential fields, paid-model calls or automatic uploads to make a connection look live. Qualify and authorize a suitable backend before changing that boundary.
