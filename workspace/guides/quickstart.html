Quickstart / No code needed

Build context, step by step.

Start with an empty workspace. Add the meaning your consumer needs. Check it, save it, find it and inspect what you will export.

Your browser holds your work. This open-source project runs in your browser. The application does not upload your context, connect to a source or call a model. Storage belongs to this device, browser profile and website origin. It is not shared server storage, a secure vault or a backup. Do not enter passwords, tokens or sensitive source data.

Start in your own workspace

A fresh visit has no records. The optional synthetic demo has a separate workspace. Open it only when you want an example. Return to your workspace to add your own records. The demo must not replace or merge with your work.

The same URL on your phone opens that phone's local workspace. It does not load records saved on your laptop. Use a workspace export to move your work between devices.

Add your first record

  1. Choose Add context. In Context type, select Glossary term for a first record. Fill in Display name, Owner, Short description, Meaning and supporting text, and the term's Definition. Add related terms only when those records already exist.
  2. Check Readable ID. The form suggests an ID from the name. Keep it or choose another before the first save. The interface shows the ID and version before save. An ID identifies one meaning. A name can change without changing the ID. An edit creates a new version; it does not replace the old record.
  3. Choose Validate record. Inspect the field and relationship results and the proposed JSON. Fix each error. This checks the record's structure and declared links. It does not prove that the meaning is correct or that an external source is current.
  4. Choose Save record on this device. Wait for confirmed browser storage. Inspect the stored record, ID, version, source text and hash. If storage fails, the interface shows that your change is not saved. Export it before leaving.
  5. Use Find context. Search by ID, name, alias or description. Filter by layer or type. Open a result to inspect its current version and pinned relationships. This is authoring search; it can include local drafts. To edit, choose Create next version; the ID stays fixed. Older versions remain in the exact stored-state JSON and workspace backup.

For example, you can enter the invented name Customer, the ID TERM_CUSTOMER and the definition An account that can place an order. This is an example to type and review, not a supplied business definition.

Keep small records and link them. Do not put a whole policy library, formula and glossary into one text field.

A relationship pins an ID and version. Add the referenced records first, or import a valid complete set. Missing records, wrong types, dependency cycles and conflicting versions need correction before a consumer payload can be made.

The internal and restricted labels describe records. They do not create browser access controls. A person who can use this browser profile may be able to read its stored context.

Import context without code

In Add context, choose Import a record for one record exported in the supported JSON, YAML or Markdown profile. Choose the format, inspect the submitted content, then choose Validate import before save. Import does not fetch the links in a document or approve its meaning.

  • JSON: use the exact record fields. Repeated keys and unknown fields fail validation.
  • YAML: use the documented bounded block profile. Quote text that could be read as a number, date or Boolean. Arbitrary YAML, tags, aliases and ambiguous values are not supported.
  • Markdown: use an exported Prefrontal record template. It has a fixed title, a JSON metadata block and a Narrative section. An arbitrary Markdown page is not a record import.

Use the Document type to enter supporting material that does not already use the record profile. Keep what the source actually says. Do not invent missing metadata or remove caveats to pass validation.

Compose and inspect a consumer payload

Open Compose and export. Choose a measure and its required point-of-view selectors. For knowledge-only context, leave the measure empty and choose records in Supporting context. A member supplies one value in one typed dimension. For example, M_GROSS_ADDS + CHANNEL_ONLINE + PRODUCT_POSTPAID + PERIOD_2026_09 names separately defined records. It does not create a stored record for every possible combination.

Choose Validate and compose. Inspect the selected IDs, versions, dependency records, provenance and validation results before Download consumer payload. Correct missing required selectors, two members from one dimension, unsupported cuts or ambiguous aliases.

The consumer preview shows what leaves this workspace. It contains context and its limits, not a calculated business answer. Its execution_authorized value is false. A downstream system must admit the proposals, check human approval, revalidate current authority and use its own source permissions before execution.

In a record's inspection view, Save local review note records an attestation against its exact hash. It is not an authenticated independent review, a backend release or permission to use a source. A new record version needs a new review.

A submission hash can show that the stored submission bytes match. It does not verify an external document, source data, freshness claim or business fact.

Guided lists use one item per line and other names use commas. The form removes surrounding space from IDs, names, owners and list items, and converts date controls to UTC. Inspect the proposed JSON before save. Meaning and supporting text stays text; it is not a model-generated summary.

Export before you leave

Open Storage and recovery. Use Download workspace backup and keep the downloaded file outside the browser. A record export is useful for one proposal; a consumer export is useful for delivery. Neither includes a complete workspace backup. In particular, the consumer payload omits the original submission files.

To recover or move a workspace, choose or paste the backup and select Validate backup. Inspect the workspace name, mode, record count and validation result. Export the current work you need to keep. Select the explicit confirmation checkbox, then Replace this workspace. The backup replaces only the selected matching mode; a demo backup cannot replace a user workspace. Nothing is merged silently.

If saved data cannot be read

The application leaves the unreadable stored value unchanged and shows a warning. Ordinary Save cannot replace it. There is no automatic clear or reset.

  1. Open Storage and recovery, then Inspect the exact stored state. Keep a copy of that raw value if you need it. A backup of current readable page state is not a backup of unreadable stored bytes.
  2. Choose or paste a valid backup for the selected user or demo mode. Select Validate backup. Inspect the backup preview and the warning that recovery will replace the captured unreadable value in this slot.
  3. Select the explicit replacement checkbox, then Replace this workspace. Only that selected slot can be replaced. Success is shown after confirmed persistence; the other workspace stays unchanged.
  4. If the stored value changed, disappeared or became a valid workspace in another tab, recovery stops with a conflict. Read stored state again or reload, inspect it and validate the intended backup again. Do not force a replacement.

You can name a new empty workspace here with Workspace name and Create workspace on this device. Use Read stored state again to inspect the current persisted state.

The user storage key is prefrontal.workspace.v1.user. The demo key is prefrontal.workspace.v1.demo. These keys are local to the current website origin and browser profile. A local preview and the published Pages URL have different storage. Other Pages projects on the same owner.github.io host share the origin; a different repository path is not a storage or security boundary.

Stored bytes cannot be readInspect and keep the raw value if needed. Validate a matching workspace backup, inspect the recovery warning and confirm Replace this workspace. Ordinary Save cannot overwrite unreadable data.
